# Incident Runbook

1. Identify the affected repository, release, environment, and user impact.
2. Stop unsafe writes when data integrity is at risk.
3. Preserve logs, request identifiers, and deployment metadata.
4. Roll back only with the accepted rollback procedure.
5. Verify service and data after mitigation.
6. Record timeline, cause, corrective actions, and follow-up owner.

Do not expose sensitive incident detail in public status messages.
