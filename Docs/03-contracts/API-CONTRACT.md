# API Contract

## Base rules

- New stable endpoints use `/api/v1/`.
- Public endpoints are anonymous and published-only.
- Admin endpoints require an authenticated, authorized session.
- JSON uses UTF-8 and explicit locale values: `fa` or `en`.
- Breaking changes require a new API version.
- OpenAPI generated by the backend is the schema authority after migration validation and artifact acceptance under `OPENAPI-ARTIFACT-CONTRACT.md`.

## Preserved legacy entry points

The migrated backend currently exposes public routes under `/api/`, admin routes under `/api/v1/admin/`, health under `/health/`, media under `/media/`, and preview under `/preview/`.
Route normalization is a planned compatibility task, not an unreviewed rename.

## Pre-scaffold public-client baseline

Until a separately accepted `/api/v1/` public projection exists, the new public site uses the reviewed `0.4.0` public schema under `/api/`. It must not invent a `/api/v1/` prefix. This is a compatibility baseline, not a claim that the unversioned surface is permanently stable.

For the new public client, canonical endpoint families are:

| Content family | Canonical path prefix | Explicitly not used by the new client |
|---|---|---|
| Articles / Writing | `/api/articles/{locale}` | Legacy `/blog/**` URLs remain redirect-only at the frontend layer |
| Publications | `/api/publications/{locale}` | `/api/research/publications/{locale}` |
| Projects | `/api/projects/{locale}` | `/api/research/projects/{locale}` |
| Teaching | `/api/teaching/{locale}` | `/api/courses/{locale}` |
| Creative | `/api/creative/{locale}` | `/api/creative-works/{locale}` |
| Research topics and statements | `/api/research/topics/{locale}` and `/api/research/statements/{locale}` | No fabricated aggregate endpoint |

The deprecated aliases remain backend compatibility surfaces only until the backend deprecation plan is accepted. Generated client types must expose only the canonical rows above.

## Locale-safe site settings rule

`GET /api/site` is not locale-qualified. Until the backend exposes an accepted localized site-settings projection, public frontend pages may consume only locale-neutral operational fields from it: `primaryColor`, approved download identifiers/URLs, and contact fields that the owner has explicitly marked locale-independent. The frontend must not render `brandName`, `tagline`, `footerText`, `seoDefaultTitle`, or `seoDefaultDescription` from this endpoint. Those strings come from an approved localized profile/content projection or are omitted.

## Consumer rule

Public-site and admin-panel adapters must fail closed on invalid payloads.
No consumer may silently invent a missing field.
No frontend generates types or claims endpoint support until its matching accepted public or authenticated-admin schema artifact exists.
